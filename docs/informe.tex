\begin{abstract}
Este proyecto documenta la evolución técnica de un sistema de visión por computadora implementado en \textbf{Haskell}. Originalmente concebido como un clasificador de razas de gatos utilizando algoritmos clásicos (KNN), el proyecto evolucionó hacia una arquitectura híbrida distribuida capaz de integrar Deep Learning (CNN) mediante \textbf{Hasktorch}. Se detalla el proceso de investigación, los desafíos de interoperabilidad entre Haskell, C++ y Python, y el uso de Inteligencia Artificial Generativa como herramienta de asistencia. El resultado final es un sistema robusto capaz de operar en tiempo real, demostrando la viabilidad de la programación funcional en aplicaciones modernas.
\end{abstract}

El KNN es un algoritmo de aprendizaje supervisado clasificado como:
\begin{itemize}
    \item **No Paramétrico:** No asume una distribución estadística en los datos.
    \item **Aprendizaje Basado en Instancias (Lazy Learning):** A diferencia de los modelos que generalizan una función durante el entrenamiento, el KNN \textbf{no aprende explícitamente}. Simplemente memoriza los datos. La generalización se pospone hasta el momento de la consulta, lo que lo hace computacionalmente costoso en inferencia ($O(N)$) pero nulo en entrenamiento.
\end{itemize}

Matemáticamente, se basa en la \textbf{Distancia Euclidiana}:
$$ d(p,q) = \sqrt{\sum_{i=1}^{n} (q_i - p_i)^2} $$

\subsection{Deep Learning (CNN)}
Se utiliza una Red Neuronal Convolucional (ResNet-18) pre-entrenada. A diferencia del KNN, este modelo es un ejemplo de \textbf{Eager Learning}: ha aprendido patrones complejos (bordes, texturas) previamente, condensando el conocimiento en una matriz de pesos (Tensores), permitiendo una inferencia $O(1)$.

\section{Implementación en Haskell}
\label{sec:funcional}

Haskell aporta garantías formales de corrección. A continuación se detalla la implementación de los pilares del paradigma:

\subsection{Funciones Puras}
\textbf{Definición:} Una función pura siempre devuelve el mismo resultado para las mismas entradas y no tiene efectos secundarios.
\textbf{Aplicación:} El núcleo del algoritmo KNN (`Classifier.hs`) es totalmente puro, facilitando pruebas unitarias y razonamiento matemático.
\begin{lstlisting}
euclideanDistance p q = sqrt $ sum $ zipWith (\x y -> (x - y)^2) p q
\end{lstlisting}

\subsection{Inmutabilidad}
\textbf{Definición:} Los datos no pueden modificarse.
\textbf{Aplicación:} El conjunto de entrenamiento (`[LabeledPoint]`) es inmutable. En lenguajes imperativos, existe el riesgo de corromper los datos durante la ejecución; en Haskell, la integridad está garantizada por el compilador.

\subsection{Tipos de Datos Algebraicos (ADTs)}
\textbf{Definición:} Mecanismo para construir estructuras complejas (Tipos Producto y Suma).
\textbf{Aplicación:} Usado para `LabeledPoint` (contiene una Etiqueta Y un Vector), impidiendo estados inválidos.

\subsection{Evaluación Perezosa (Lazy Evaluation)}
\textbf{Definición:} Haskell no evalúa una expresión hasta que su resultado es estrictamente necesario.
\textbf{Aplicación Crítica:} En el módulo de \textit{Hasktorch}, la lista de 1000 etiquetas de ImageNet no se carga en memoria al inicio. Solo se evalúa la cadena específica necesaria para imprimir el resultado final, optimizando recursos.

\subsection{Mónada IO}
El sistema distingue estrictamente entre código puro y código que interactúa con el mundo. `Main.hs` utiliza la mónada `IO` para orquestar la lectura de imágenes, garantizando que la lógica de permanezca pura.

\section{Bitácora de Desarrollo y Metodología}

El desarrollo fue un proceso iterativo de resolución de problemas técnicos complejos.

\subsection{Fase 1: El Clasificador KNN}
Se intentó usar la librería \texttt{JuicyPixels} para extraer histogramas de color en Haskell puro. Aunque el código era correcto, el costo computacional de procesar miles de imágenes resultó ineficiente. Se tomó la decisión de ingeniería de delegar la extracción a Python, manteniendo la lógica de clasificación (pura) en Haskell.

\subsection{Fase 2: Integración con Hasktorch}
Se exploró \textbf{Hasktorch} para mejorar la precisión.
\begin{itemize}
    \item **Obstáculo:** La documentación era escasa y existían incompatibilidades de versión entre GHC y las librerías C++.
    \item **Solución:** Se analizó el repositorio oficial, identificando el ejemplo `load-torchscript` como base. Tras horas de compilación y ajuste de dependencias (`libtorch`), se logró un ejecutable funcional.
\end{itemize}

\subsection{Fase 3: Tiempo Real y Webcam}
Para lograr detección en tiempo real, se superó el reto de llamar al binario de Haskell desde Python. Se diagnosticó que las variables de entorno (\texttt{LD\_LIBRARY\_PATH}) no se heredaban, causando fallos silenciosos. Se implementó un wrapper con \texttt{shell=True} para replicar el entorno de la terminal.

\subsection{Uso de Herramientas de IA}

El desarrollo de este proyecto involucró la integración de ecosistemas tecnológicamente dispares (GHC/Haskell y C++/LibTorch). Para acelerar la resolución de problemas de bajo nivel y la arquitectura de software, se utilizó Inteligencia Artificial Generativa como herramienta de consultoría técnica.

Se utilizaron asistentes (DeepSeek, Gemini) para documentación y depuración. Prompts clave incluyeron:

\begin{description}
    \item[Arquitectura de Software Híbrida:]
    \textit{"Diseña un patrón de arquitectura para orquestar un binario compilado de alto rendimiento (Haskell) desde un entorno de script dinámico (Python), garantizando la persistencia de datos y la sincronización de procesos mediante el sistema de archivos."}
    
    \item[Resolución de Conflictos de Enlazado (Linker Errors):]
    \textit{"Analiza la salida de error de GHC al intentar vincular \texttt{hasktorch} con \texttt{libtorch} en Linux. Proporciona una solución para configurar \texttt{cabal.project.local} y las variables de entorno \texttt{LD\_LIBRARY\_PATH} para resolver referencias indefinidas a símbolos de C++."}
    
    \item[Optimización de Inferencia:]
    \textit{"Compara las estrategias de evaluación perezosa (Haskell) versus la ejecución ansiosa (Python) en el contexto de la carga de modelos de Deep Learning. ¿Cómo se puede mitigar la latencia de inicialización al procesar un flujo de video en tiempo real?"}
    
    \item[Paradigmas de Programación:]
    \textit{"Explica cómo modelar un clasificador KNN utilizando exclusivamente funciones puras y tipos de datos algebraicos inmutables, contrastando este enfoque con una implementación imperativa basada en arrays mutables."}
\end{description}

\subsection{Contribución Open Source}
Se identificó la falta de documentación para inferencia en tiempo real en el repositorio de Hasktorch. Se preparó una contribución (Pull Request) con el script `webcam.py` para facilitar el acceso a futuros estudiantes.

\section{Impacto, Aplicaciones y Futuro}

La arquitectura desarrollada trasciende el ejercicio académico, sentando las bases para sistemas autónomos robustos gracias a la seguridad de tipos que ofrece Haskell.

\subsection{Aplicaciones Prácticas}
Este sistema tiene aplicaciones reales más allá de lo académico:

\begin{itemize}
    \item \textbf{Sistemas Embebidos (IoT):} El binario compilado es eficiente y autocontenido. Es ideal para dispositivos como Raspberry Pi, donde los recursos son limitados y la estabilidad es crítica.
    \item \textbf{Monitoreo Científico:} Cámaras trampa autónomas para registrar fauna silvestre en zonas remotas.
    \item \textbf{Pedagógico:} Sirve como referencia de integración de paradigmas (Funcional + Imperativo) para estudiantes de ingeniería en computación.
\end{itemize}

\subsection{El "Robot Biólogo": Monitoreo Ambiental}
La capacidad de ejecutar modelos de Deep Learning (ResNet) mediante un binario compilado abre la puerta al desarrollo de sistemas para la conservación de la naturaleza.
\begin{itemize}
    \item **Detección de Eventos Ecológicos:** Un sistema desplegado en campo capaz de discriminar no solo movimiento, sino la \textit{semántica} de la escena (ej. distinguir un jaguar de un venado).
    \item **Etología Computacional:** Podría registrar interacciones complejas, como la "amistad" o simbiosis entre especies, depredación o comportamientos migratorios, filtrando datos irrelevantes en el origen.
\end{itemize}

\subsection{Domótica para Mascotas (Pet Tech)}
En el ámbito doméstico, este clasificador puede integrarse para mejorar el bienestar animal:
\begin{itemize}
    \item **Comedero Automático Inteligente:** Utilizando el reconocimiento de patrones (KNN o CNN), un dispensador podría abrirse únicamente para un gato específico (ej. uno con dieta médica), bloqueando el acceso a otras mascotas.
    \item **Puertas Inteligentes:** Una gatera automatizada que detecta si el gato trae una presa (ratón o pájaro) en la boca —diferenciando la forma del objeto— y bloquea la entrada para evitar "regalos" no deseados.
\end{itemize}

\section{Conclusiones y Trabajo Futuro}

Este proyecto ha validado empíricamente la viabilidad de utilizar \textbf{Haskell} no solo como una herramienta teórica, sino como un motor de inferencia robusto en aplicaciones de Visión por Computadora en tiempo real.

\subsection{Síntesis Técnica}
La implementación demostró dos facetas del paradigma funcional:
\begin{enumerate}
    \item \textbf{Claridad Algorítmica:} La implementación del clasificador KNN evidenció cómo la inmutabilidad y las funciones de orden superior (\texttt{map}, \texttt{fold}) permiten expresar algoritmos matemáticos de forma concisa y verificable, alineándose perfectamente con la naturaleza del aprendizaje perezoso.
    \item \textbf{Potencia de Cómputo:} La integración con \textbf{Hasktorch} probó que Haskell puede operar al nivel del estado del arte (SOTA), sirviendo como una capa segura de alto nivel sobre motores de tensores optimizados en C++.
\end{enumerate}

\subsection{Validación de la Arquitectura Híbrida}
La arquitectura distribuida localmente (Python para E/S y Haskell para Lógica) resultó ser una estrategia de ingeniería exitosa. Se superó la barrera de la falta de drivers nativos de webcam en Haskell delegando esta tarea a Python, mientras se preservaban las garantías de seguridad de tipos en el núcleo de decisión.
La solución al problema de enlazado dinámico (\textit{linking hell}) mediante el uso de \texttt{subprocess} con herencia de entorno (\texttt{shell=True}) establece un patrón reutilizable para futuros proyectos que busquen integrar binarios compilados con scripts de automatización.

\subsection{Reflexión Final}
Si bien la curva de aprendizaje para configurar el entorno de \textit{Deep Learning} en Haskell es pronunciada, el resultado es un sistema modular donde la lógica de negocio es pura y fácil de testear. Este proyecto sienta las bases para aplicaciones más complejas, como sistemas embebidos en robótica o monitoreo biológico automatizado, donde la fiabilidad del software es tan crítica como su capacidad de percepción.
